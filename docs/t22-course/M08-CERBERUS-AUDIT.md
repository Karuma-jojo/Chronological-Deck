## Adversarial passes

### A. Novice/prerequisite pass

The module assumes mathematical content only from M01, M03 and M04. Python syntax used for the first time is taught before use. M07 vocabulary is intentionally absent because the canonical dependency graph does not require M07.

High-risk bridges explicitly taught before assessment include: assignment versus equality; half-open ranges; first-match branching; mutable aliasing; exact rational construction; conditioning denominator; PRNG state versus seed; assert-versus-runtime validation.

### B. Wrong-solver pass

Transfers were designed to make plausible wrong models visibly fail. Examples include:

- S03: overlapping `x>=0` makes the zero branch unreachable.
- S04: `range(1,5)` silently omits the intended fifth square.
- S05: `while x != 10` never terminates under +3 steps.
- S10: `[[0,0]]*3` repeats one mutable inner reference.
- S11: default `zip` silently truncates misaligned paired data.
- S12: `>4` instead of `>=4` changes exact event probability from 2/3 to 1/3.
- S13: `Fraction(0.1)` preserves the binary-float value, not intended 1/10.
- S14: dividing conditional hits by 36 computes the joint probability, not the conditional.
- S15: “different properties” fails the exact product criterion for independence.
- S16: averaging distinct payoff values instead of probability-weighting produces 2 instead of 0.
- S17: `assert` is rejected as the sole essential runtime contract.
- S19: reseeding inside every trial repeats the same initial state.
- S20: `U>p` simulates the complement.
- S22: a state snapshot, not merely the original seed, replays a mid-run suffix.
- S23: `b=a` collapses a 36-pair independent-dice model to six diagonal pairs.
- S24: three independent defects—missing face6, reused draw, wrong event inequality—must be repaired before discussing N.

### C. Prompt ↔ rubric fairness pass

Every scoring row was re-read against the public prompt. Two defects were found before closure and repaired:

1. **S17 observability gap:** ownership required a discriminating boundary case but the Main did not publicly ask for one. The Main now explicitly asks for a boundary input distinguishing `x>=5` from `x>5`; its rubric has a dedicated row.
2. **S18 assessment gap:** the lesson warned against broad catch-and-ignore behavior but no public task observed that judgment. The Transfer now asks why `try/except Exception: pass` is an unacceptable repair and scores the explanation.

No unpublished obligation is intentionally scored.

### D. Claim-to-evidence pass

`docs/t22-course/audit/m08-semantic-contract.json` pins all 120 builder-reviewed links to explicit public tasks and exact rubric-row numbers. The final mappings were manually re-linked after S17/S18 repairs rather than generated by “claim i → row i”.

Mutation checks deliberately substitute an existing but semantically wrong rubric row/task and require failure.

### F. Separation pass

Each session stores Main/Transfer-specific distinguishing fragments. The structural guard requires each fragment to occur in the public fixed task and not in the lesson. This is a cheap first filter; the builder also read the mathematical/code instances semantically. Generic methods such as use of `range`, `Fraction` or `Random` are intentionally teachable and are not treated as contamination.

### G. Boundary pass

Forbidden downstream material is not owned here: NumPy, pandas, vectorization, plotting, formal Monte Carlo diagnostics, inference/LLN/CLT, backtesting and market-data engineering remain downstream. M09 remains closed.

## Remaining limitations

- This is a builder self-review, not an independent Astra acceptance.
- The module verifies Python semantics and representative executable oracles, but a learner trial has not yet been observed.
- Static rubrics cannot prove that every future equivalent code formulation will be judged perfectly; marking explicitly accepts equivalent correct Python/pseudocode.
- PRNG reproducibility claims intentionally follow Python documentation and avoid promising cross-version fixed sequences for helper algorithms such as `randrange`.
